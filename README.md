Cross-platform SSH server setup automation toolkit. Installs, configures, and enables SSH server on Windows, Linux, and macOS — generating key pairs, configuring authentication, and applying secure permissions — in a single run per platform.

---

## Purpose

Manually configuring SSH on a fresh OS install or a new machine involves multiple disjoint steps: installing packages, editing configuration files, enabling services, opening firewall ports, generating keys, and setting correct file permissions. This project consolidates all of that into three platform-specific scripts, each performing the complete setup automatically.

Target audience: developers, system administrators, and DevOps engineers who need to bootstrap SSH access quickly and consistently across heterogeneous environments.

---

## Features

- **Cross-platform support**: dedicated scripts for Windows, Linux, and macOS
- **Automatic package/service detection**: Linux script detects the package manager (apt, dnf, pacman) and the correct systemd service name (ssh or sshd)
- **Automatic SSH key generation**: generates an Ed25519 key pair (`id_ed25519`) when one does not already exist
- **Authorized key registration**: appends the generated public key to `authorized_keys`, skipping duplicates
- **Dual authentication**: enables both password-based and public-key authentication in `sshd_config`
- **Firewall configuration**: Windows script adds an inbound firewall rule for TCP port 22
- **Service lifecycle management**: starts, enables on boot, and restarts the SSH service
- **Secure permissions**: applies restricted file permissions to the `.ssh` directory and its contents
- **Idempotent execution**: skips already-installed components, existing keys, and duplicate authorized keys
- **Connection instructions**: prints the SSH connection command upon completion

## Architecture

No frameworks, libraries, or external dependencies beyond the OS-native tooling are used. Each script is self-contained and communicates only with the operating system's built-in facilities.

### Request Flow (user → target machine)

```
User (client machine)
  │
  ├── ssh babar@<ip-address>        ← command printed by the script
  │
  ▼
Target machine (sshd listening on :22)
  │
  ├── PasswordAuthentication yes  → password prompt
  └── PubkeyAuthentication yes    → key-based auth (no password if key matches)
```

### Script Execution Flow

All three scripts follow the same logical phases:

```
1. Install SSH daemon (if missing)
2. Start the SSH service
3. Enable SSH service on boot
4. Configure sshd_config (PasswordAuthentication, PubkeyAuthentication, ListenAddress)
5. Create ~/.ssh directory with secure permissions
6. Generate Ed25519 key pair (if missing)
7. Add public key to authorized_keys (if not already present)
8. Set secure file permissions
9. Restart SSH service
```

### Authentication Flow

1. On first run, `ssh-keygen -t ed25519` creates `~/.ssh/id_ed25519` (private) and `~/.ssh/id_ed25519.pub` (public).
2. The public key content is appended to `~/.ssh/authorized_keys` if not already present.
3. `sshd_config` has both `PasswordAuthentication yes` and `PubkeyAuthentication yes` — the SSH server accepts either method.
4. On Windows, `icacls` removes inheritance and grants explicit permissions to the user, SYSTEM, and Administrators.
5. On Linux/macOS, `chmod 700 ~/.ssh` and `chmod 600 ~/.ssh/authorized_keys` are applied.

## Core Components

### Windows — `setup-ssh.bat`

| Step | Implementation |
|---|---|
| Admin check | `net session` — exits if not running as Administrator |
| Install OpenSSH | PowerShell `Add-WindowsCapability` for `OpenSSH.Server` and `OpenSSH.Client` |
| Service configuration | `Set-Service -StartupType Automatic` and `Start-Service` for `sshd` |
| Firewall | `New-NetFirewallRule` for TCP port 22, inbound, named `OpenSSH-Server-In-TCP` |
| sshd_config | Regex-based update to ensure `PasswordAuthentication yes`, `PubkeyAuthentication yes`, `ListenAddress 0.0.0.0` |
| Key generation | `ssh-keygen -t ed25519 -N ""` via system OpenSSH or PATH |
| Permissions | `icacls` with inheritance removal and explicit grant to user, SYSTEM, Administrators |

### Linux — `setup-ssh.sh`

| Step | Implementation |
|---|---|
| Package manager detection | Checks `apt-get`, `dnf`, `pacman` in order; installs `openssh-server` |
| Service name detection | Queries `systemctl list-unit-files` for `ssh.service` or `sshd.service` |
| sshd_config | `sed`-based `set_sshd_option` helper function |
| Key generation | `ssh-keygen -t ed25519 -N ""` |
| authorized_keys | Appends public key only if not already present (`grep -qxF`) |
| User ownership | If run via `sudo`, changes `.ssh` ownership back to the original user |
| Permissions | `chmod 700 ~/.ssh`, `chmod 600 ~/.ssh/authorized_keys` |

### macOS — `setup-ssh.sh`

| Step | Implementation |
|---|---|
| Enable Remote Login | `sudo systemsetup -setremotelogin on` |
| sshd_config | `sed -i ''` (BSD sed syntax) via `set_sshd_option` helper |
| Key generation | `ssh-keygen -t ed25519 -N ""` |
| authorized_keys | Same duplicate-safe append logic as Linux script |
| Service restart | `launchctl kickstart -k system/com.openssh.sshd` (preferred), fallback to `stop`/`start` |
| Permissions | Same as Linux script |

## Configuration

### SSH Daemon Configuration (`sshd_config`)

All three scripts modify `/etc/ssh/sshd_config` (Linux/macOS) or `%ProgramData%\ssh\sshd_config` (Windows) to ensure the following directives are set:

| Directive | Value | Purpose |
|---|---|---|
| `PasswordAuthentication` | `yes` | Allow password-based login |
| `PubkeyAuthentication` | `yes` | Allow public key authentication |
| `ListenAddress` | `0.0.0.0` | Listen on all IPv4 interfaces |

Existing values (even if commented out) are replaced in-place.

## How It Works

1. A user clones the repository and runs the appropriate script for their operating system.
2. The script checks for administrative privileges (`net session` on Windows, `EUID` check on Linux/macOS) and exits early if insufficient.
3. The SSH server package or Windows capability is installed if not already present.
4. The SSH service is started and configured to start automatically on boot.
5. The `sshd_config` file is modified to enable password authentication, public key authentication, and listening on all IPv4 interfaces (`0.0.0.0`).
6. The `~/.ssh` directory is created with secure permissions.
7. An Ed25519 key pair is generated at `~/.ssh/id_ed25519` only if one does not already exist.
8. The public key is appended to `~/.ssh/authorized_keys` — duplicate entries are prevented.
9. Strict file permissions are applied (Windows: `icacls`; Linux/macOS: `chmod 700/600`).
10. The SSH service is restarted to pick up the configuration changes.
11. The script prints the SSH connection command the user can run from another machine to connect.
